# ShellRS 使用手册

[返回 README](../README.zh-CN.md) · [English](manual.md)

基于 GPUI Kit 的中文 SSH 主机管理工具，提供持久化的主机与分组、可在多台主机间共用的登录凭据、本地终端、SSH 多终端、经终端连接的文件上传下载和 SSH 端口转发。

标题栏「ShellRS」后面的三个图标切换左侧栏显示的内容：主机列表、端口转发列表或凭据列表。侧栏隐藏时点其中一个会把它重新展开。左侧栏的显示或隐藏状态会自动保存，下次启动时恢复；首次启动默认显示。侧栏开关位于主机面板右边界上方的右侧，根据展开或收起状态切换图标，并分别提示「隐藏侧栏」或「显示侧栏」；拖动主机面板的右边缘可以调整宽度，默认 280 像素、最窄 180 像素，下次启动照旧（见「应用 → 窗口」）；拖动时按钮跟着移动，面板比标题栏的三个图标还窄时停在图标右边，收起后仍停在原位置。标题栏右侧从左到右是快速连接（搜索图标）、临时连接（闪电图标）和本地终端（终端图标）；连接按钮只显示图标，悬停可查看用途。

ShellRS 同一时间只运行一个：已经开着时再打开一次，会把已有的窗口调到前面，新启动的那个随即退出。两个 ShellRS 各自把主机读进内存再写回同一个数据库，会互相覆盖对方的改动。（用 `SHELLRS_DATA_DIR` 指到不同数据目录的算不同的 ShellRS，可以同时运行；Windows 的安装版和便携版也是这样。）要并排看两个终端，把标签拖成分栏即可。

在 macOS 上，点窗口左上角的关闭按钮只是把 ShellRS 隐藏到后台：已打开的连接、文件传输和端口转发照常运行，点 Dock 图标恢复窗口，原来的标签都在。要真正退出用 ⌘Q，或者右键 Dock 图标选「退出」。菜单栏和其他 Mac 应用一样：「ShellRS」菜单里有关于、设置、隐藏 ShellRS（⌘H）、隐藏其他（⌥⌘H）、全部显示和退出，「窗口」菜单里有最小化（⌘M）和缩放。Linux 上关闭窗口就是退出。

Windows 默认关闭窗口时退出。在「设置 → 应用 → 窗口」开启「关闭窗口时最小化到托盘」后，点「×」只隐藏窗口，连接、传输和端口转发继续运行。单击托盘图标或从它的右键菜单选择「显示窗口」恢复窗口，选择「退出」才真正结束程序；有未保存的编辑内容时仍会先确认。再次启动 ShellRS 或使用全局显示快捷键也能恢复窗口。这个选项默认关闭，只在 Windows 显示。托盘图标创建失败时会提示错误并保持窗口打开。

## 主机列表

左侧栏里保存的每一项是一台主机：地址、端口和认证方式。同一台机器用不同用户登录，就保存成两台主机。名称可以留空，保存时默认使用地址；也可以填写自定义名称。

名称下面的「协议」选 SSH、Telnet 或串口。编辑主机时也可以换协议：表单里共有的项（名称、地址、分组、连接方式、备注等）沿用，其余是新协议的默认值。SSH 主机被别的主机当作跳板、或有端口转发经由它时，只能是 SSH。下面先说 SSH 主机，Telnet 主机和串口主机见本节末尾。

主机对话框的「认证方式」有三种：

- **密码**：填用户名和密码，密码保存在系统钥匙串；密码留空则每次连接时询问。只用密码登录，不会先拿 SSH Agent 或私钥去试。服务器只在键盘交互式认证里收密码时（如 ESXi），保存的密码会自动回答它唯一的隐藏问题；还有验证码等别的问题时照样询问。
- **使用凭据**：选一条保存好的凭据，用户名和登录方式都来自凭据（见下面「凭据」），对话框里不再填用户名和密码。「测试连接」同样使用凭据保存的密码。要用私钥登录，就建一条密钥凭据。
- **无密码**：只填用户名。依次尝试服务器免认证、SSH Agent 和 `~/.ssh` 下的默认私钥（`id_ed25519`、`id_ecdsa`、`id_rsa`），和命令行 `ssh` 默认的做法一样。服务器要求密码时连接失败并说明原因，不会询问；服务器在密钥之后再要验证码时照样询问。

无论选哪种，连接时都先问服务器是否允许免认证登录，允许就直接登录。「测试连接」时选了「密码」却没填，就像「无密码」那样试一遍（免认证、SSH Agent、默认私钥），连不上就说明原因。

主机对话框「分组」下面的「连接方式」决定怎么连到这台主机，终端、文件传输、端口转发和「测试连接」都照它走：

- **直接连接**：默认，本机直接连主机的地址和端口。
- **SSH 跳板**：经过别的已保存主机连过去，支持多级。框里一排标签写出整条路（「本机 → 阿里云99 → 禅道 → 当前主机」），下面每台跳板一行，「×」移除，「添加跳板主机」可按名称或地址搜索；要调顺序就移除后重新添加。连接时先登录第 1 台，由它连第 2 台，依此类推，最后一台连到主机。每台跳板都用它自己的地址、端口、认证方式（密码、凭据或无密码）和主机信任记录，首次连接各问一次主机密钥，询问框里写明是哪台跳板主机；跳板主机自己的「连接方式」在这里不生效，要多级就在这里按顺序列出。主机的地址按跳板主机那边的网络来填，例如内网地址。
- **代理连接**：经由 HTTP 代理（`CONNECT`）或 SOCKS5 代理连接，在下拉框里选。填代理的地址和端口（例如本机的 `127.0.0.1:7890`）；代理需要认证时再填用户名和密码，密码保存在系统钥匙串，经由同一个代理、同一个用户名的主机共用。主机的地址交给代理去解析。代理要求认证却没有密码、或者拒绝了用户名和密码时，连接失败并说明原因，不会询问。

已经打开的标签各自记着打开时的主机：编辑主机（改名称、地址、协议等）不影响它们，标题、图标、状态栏和重新连接都照打开时的来，要用新的设置就新开一个标签；删除主机也不关闭它的标签，只是标签菜单里少了「编辑主机…」这类要用到主机本身的项。删除一台被别的主机用作跳板的主机，确认框写明有几台主机在用它；删除后那些主机的跳板列表里留下一行「已删除的主机」，连接时直接报错，不会悄悄改成直连或少跳一级，编辑时移除或换一台即可。已经打开的连接不受影响。

**尚未实现：跳板和代理叠加使用、拖动调整跳板顺序、HTTPS 代理、在主机列表里标出连接方式。**

对话框最后是「备注」，可以写多行（回车换行），记下机器的用途、负责人、到期时间之类，只保存在本地数据库里，不影响连接。

主机前面的图标是连接时探测到的系统徽章，还没探测到系统时是名称的首字。没有品牌色的图标（首字，以及 macOS 和 AlmaLinux 的徽章）按地址取一个固定的颜色，串口主机按串口设备取，同一个地址总是同一种颜色。Telnet 和串口主机没有系统可探测，图标总是名称的首字。

鼠标停在主机上，行的右侧会显示 `用户@地址:端口`，主机有备注时下面接着显示备注（太长的只显示前 6 行）。右键主机可连接、编辑、创建副本、复制 IP（地址是域名时叫「复制主机名」）、复制 ID 或删除。「复制 ID」复制的是主机的 16 位随机标识（形如 `Jwg5rHvXCxw89paM`），供其他工具标识这台主机：它在主机创建时生成，改名、改地址都不变，创建的副本得到新的 ID，删掉的 ID 不会再分配。没有打开任何标签时，中间区显示「最近连接」列表，双击或回车连接；右键其中的主机弹出同一个菜单，并选中该主机。

列表上方「新建主机…」左边的「快速连接」打开一个搜索框，列出所有保存的主机：最近连接过的在前，其余按名称排，每行写着分组和 `用户@地址:端口`。输入名称、地址、用户名、备注或分组里的字就能筛选，几个词用空格隔开时都要匹配。打开时不高亮任何一台；输入后高亮第一个匹配的，回车就连它；也可以 ↑↓ 移动，或者直接单击一台连接。

列表上方的搜索框（⌘K，其他平台 Ctrl+K）按名称、地址、用户名筛选主机，也按名称找分组：分组名匹配时列出这个分组和它下面的全部子分组、主机。结果都展开，匹配的主机连同它所在的各级分组一起显示。回车连接第一台匹配的主机（按列表里的顺序；只因分组匹配而列出的主机不算）。Esc 清空搜索。

拖动分组或主机到同类项目的上侧 / 下侧可调整同级顺序；主机拖到分组会移入该分组，分组拖到另一个分组的中部会成为子分组。拖到列表空白处可移回根层级。分组始终排在同级主机之前，顺序与分组的展开状态会保存到本地数据库。搜索时暂停拖动排序。

**导入主机**：主机列表标题栏的「…」菜单和列表空白处的右键菜单里有「从 ~/.ssh/config 导入…」和「从 ~/.ssh/known_hosts 导入…」，把 OpenSSH 已经知道的主机一次加进来。对话框先列出文件里的主机，勾选、改好后点「导入 N 台主机」。用户名是 `git` 的和 GitHub、GitLab、Bitbucket、Gitee 等代码托管的地址只用来推拉代码、不能登录，不列出：

- **~/.ssh/config**：每个 `Host` 行里写明的名称是一台主机（带 `*`、`?` 的通配符和 `!` 开头的不算），名称就是它的名字。设置按 `ssh -G` 的规则取：所有适用的块（含通配符的 `Host *`）按文件顺序看，每项取第一次出现的值。读 `HostName`、`Port`、`User`、`IdentityFile`（第一个），没写 `User` 时用本机当前用户名。`Include` 会读进来（相对路径在 `~/.ssh` 下，支持通配符）。`Match` 块不读（`Match all` 除外）；`ProxyJump`、`ProxyCommand` 不导入，主机按直接连接导入，跳板要导入后在主机对话框里配。地址、端口和用户名都相同的几个名称只算一台。
- **~/.ssh/known_hosts**：列出连接过的主机，同一台主机的几种密钥只算一台，`[地址]:端口` 读出端口。文件里没有用户名，都填 `root`。经过哈希的记录（`|1|` 开头，Ubuntu、Debian 默认这样存）读不出地址，对话框里写明有几条。主机密钥不会拷进 ShellRS 自己的主机信任文件，第一次连接仍会问是否信任。
- **每一行**：名称、分组、用户名可以改。分组写 `生产/华东` 这样的路径，不存在就新建，同一个新路径只建一组；留空不属于分组。「状态」列写「新增」；地址和端口都相同的主机已经保存过时写「已存在」、这一行不能勾选，导入从不修改已有的主机。
- **认证**：`IdentityFile` 指向本机存在的私钥、又不是默认私钥（`~/.ssh/id_ed25519`、`id_ecdsa`、`id_rsa`）时，这一行用密钥凭据：已有同一私钥、同一用户名的凭据就用它，否则导入时新建一条「本机文件」凭据（名称是私钥的文件名，几行共用一个私钥和用户名时只建一条），私钥复制一份进数据目录的 `keys/`；再导入同一个私钥文件时认得出这份副本，不会重复建凭据。其余默认「无密码」（会试 SSH Agent 和默认私钥）。每行的「认证」下拉也能改成「密码」或别的凭据；选了已有凭据时用户名取自凭据。
- **选择文件…**：读别处的同类文件，`Include` 的相对路径仍在 `~/.ssh` 下。macOS 的选择框里按 ⌘⇧. 显示 `.ssh` 这样的隐藏文件夹。

**Telnet 主机**用 Telnet 连接，常见的是交换机、路由器、串口服务器（每个端口对应一台设备的 Console）、GNS3 / EVE-NG 里设备的 Console 和嵌入式设备。在主机对话框的「协议」里选「Telnet」：

- **地址和端口**：同 SSH 主机，端口默认 23（新建主机时，端口没改过就随协议在 22 和 23 之间切换）。名称留空时用地址。
- **Telnet 自动登录**：默认不勾选，连上后自己在终端里输入用户名和密码。勾选后在「认证方式」里选：
  - **手动输入**：填用户名和密码，都可以留空。密码保存在系统钥匙串；留空时只输入用户名，密码连上后自己输入。设备只问密码时（如只设了 `line vty` 密码的思科设备）把用户名留空。
  - **使用凭据**：选一条密码凭据，用户名和密码都来自凭据。只列密码凭据：密钥和 SSH Agent 对 Telnet 没有用。
  - **用户名提示文本 / 密码提示文本**：设备问用户名、密码时显示的文字，留空用常见的（`login:`、`Username:`、`User Name:` 和 `Password:`），填了就只认填的。匹配时忽略大小写和行尾的空格，只看光标所在行的结尾。
- **自动登录怎么做**：看到用户名提示就输入用户名，看到密码提示就输入密码，各输入一次。先看到密码提示（设备只问密码）就直接输入密码。登录失败、又出现用户名提示时不再重试，交给你自己输入；在它输入之前你按了键，它也不再输入。
- **连接方式**：同 SSH 主机，可以直接连接、经过 SSH 跳板或代理。经过跳板时由最后一台跳板连到 Telnet 主机的地址和端口，所以地址按跳板那边的网络来填。Telnet 主机不能当跳板，端口转发也不能经由它。
- **测试连接**：照连接方式走到地址和端口，连上就断开，说明这个端口能连通；不检查自动登录。
- **连接**：打开一个终端标签，用法同 SSH 的远程终端。按 Telnet 协议告诉设备终端类型（xterm-256color）和窗口大小，窗口变化时也会告诉它；回车发送 CR LF（同 PuTTY 的默认）。设备断开（如输入 `exit`）后按 Enter 在原标签重连；改了地址、自动登录等设置，新开的标签才用新的设置。
- **菜单**：标签菜单里有「发送 Break」，发送 Telnet 的 Break，串口服务器会把它转成串口线上的 Break。没有文件传输，右侧栏只有命令片段，不探测系统、不显示延迟。
- **注意**：Telnet 不加密，用户名、密码和终端里的内容都是明文，只在可信的网络里用。终端只按 UTF-8 显示。设备不负责回显时（如国际象棋服务器、MUD，或手动输入 SMTP、HTTP、Redis 命令），ShellRS 自己显示你打的字，同 PuTTY 的默认：一行打完按 Enter 才整行发出，发出前可以用退格、Ctrl+U 修改；方向键等照常直接发送。少数自己回显却不说的设备会把字显示两遍。

**串口主机**是本机的一个串口，如 USB 转串口线、开发板的调试口、交换机和路由器的 Console 口。在主机对话框的「协议」里选「串口」：

- **串口设备**：可以手填，右端的下拉列出本机找到的串口，最后一项「重新检测」重新查找。macOS 只列 `/dev/cu.*`，Linux 是 `/dev/ttyUSB0` 这样的路径，Windows 是 `COM3` 这样的名字。名称留空时用串口设备。
- **波特率**：默认 115200，下拉里有常用值，也可以手填。
- **数据位、校验位、停止位、流控**：数据位 5–8，校验位无 / 奇校验 / 偶校验，停止位 1 / 2，流控无 / RTS/CTS / XON/XOFF；默认 8N1、无流控。不支持 Mark / Space 校验、1.5 位停止位和 DSR/DTR 流控。
- **测试连接**：按填的参数打开串口再关掉，说明能否打开；打不开时写明原因（找不到设备、已被占用、没有权限）。它只说明本机能打开这个串口，不检查另一端有没有设备在应答。
- **没有的东西**：串口主机没有地址、端口、认证方式和连接方式。它不能当跳板，端口转发也不能经由它。
- **连接**：打开一个终端标签，用法同 SSH 的远程终端。断开后（如拔掉 USB 线）按 Enter 在原标签重连；改了波特率等参数，新开的标签才用新的设置。
- **独占**：同一个串口同时只能被一个程序打开，macOS 和 Linux 上 ShellRS 也独占它。已经打开时再连接会报「已被占用」。Linux 上通常要把当前用户加入 `dialout` 组才能打开串口。
- **菜单**：串口主机的右键菜单里没有「复制 IP」。鼠标停在串口主机上显示「设备 · 115200 8N1」。

**尚未实现：堡垒机用 `telnet://` 链接拉起 ShellRS、用 XMODEM / YMODEM 传文件（ZMODEM 可以，见「终端」的「ZMODEM 传文件」）、控制 DTR / RTS 线、macOS 上用 socat 等程序造的虚拟串口（伪终端设不了波特率）。**

## 临时连接

标题栏右上角的闪电图标（临时连接）连一台主机而不保存它，适合只登一次的机器。对话框和新建主机一样填地址、端口和认证方式（密码、使用凭据或无密码），没有分组、连接方式和备注，名称可以不填（用地址）；可以先「测试连接」。「协议」选「Telnet」时填地址、端口和自动登录（密码只在内存里）；选「串口」时填串口设备和参数，直接打开一个串口。点「连接」打开一个终端标签：

- **功能齐全**：复制会话、文件传输、重新连接和右侧栏的全部工具都能用。连接方式是直接连接。
- **不保存**：不进主机列表、开始页的最近连接和数据库；它的终端标签都关掉后就没了。标签的菜单里没有「编辑主机…」。
- **密码只在内存里**：填的密码不进钥匙串，重新连接时照样用它；没填时服务器要密码就弹框问。选「使用凭据」时用凭据保存的密码或私钥。

要保存的主机在主机列表标题栏的「+」、右键菜单或 ⌘N（其他平台 Ctrl+N）新建。

## 端口转发

点标题栏的端口转发图标，左侧栏换成转发列表。每条转发规则经由一台已保存的主机，启动时为自己建立一条 SSH 连接，不依赖该主机的终端标签：关掉标签、对主机「断开连接」都不影响它，主机的连接状态也不把它算在内。有转发在运行时，标题栏的端口转发图标旁显示运行数量。

三种转发，都按「入口 → 出口 → 目标」理解，连接从入口进、经 SSH 隧道到出口、再由出口去连目标：

| 类型 | 入口（监听） | 出口 | 用途 |
| --- | --- | --- | --- |
| 本地转发（`ssh -L`） | 本机 | 服务器 | 在本机访问服务器那边的服务，例如用本机的客户端连只对服务器开放的数据库 |
| 远程转发（`ssh -R`） | 服务器 | 本机 | 让服务器那边访问本机的服务，例如把本机开发中的站点给对方看、接收 Webhook |
| 动态转发（`ssh -D`） | 本机（SOCKS 代理） | 服务器 | 把服务器当代理，目标由应用自己指定，例如让浏览器经由服务器上网 |

- **新建和编辑**：列表标题栏的「+」打开对话框。上方一行三张卡片选类型，中间的示意图随表单实时填入地址、标出入口在哪台机器上，下面一句话说明这条规则的效果（如「在本机连接 127.0.0.1:8080，就等于从 SSH 服务器连接 db.internal:3306。」）。示意图和这句话里的「SSH 服务器」就是「经由主机」选的那一台，图里按它扮演的角色称呼，不写主机的名称。示意图上有一个圆点沿连接方向缓缓移动：先过 SSH 隧道，再到目标，停一下，周而复始；切换类型时从新的入口重新出发。名称可以不填，列表里显示转发摘要（`8080 → db.internal:3306`、`9000 ← localhost:3000`、`SOCKS 1080`）。
- **启动和停止**：每行末尾的按钮，或双击该行、选中后回车；右键菜单里还有编辑和删除。「创建」只保存规则，不会自动启动。勾选「启动 ShellRS 时自动开启」的规则随应用启动。
- **状态**：行尾显示正在连接、运行中（及当前连接数）、正在重连或已停止的原因。某个连接转发不了（例如服务器连不上目标）只在该行提示，转发本身继续运行。
- **登录**：使用主机的配置、钥匙串里保存的密码和 ShellRS 自己的主机信任记录。首次连接的主机、需要输入的密码会弹出和终端一样的询问框，并注明是哪条转发在连接；取消询问等于停止这条转发。
- **断线重连**：连接中断后按 1、3、10 秒自动重连三次，重连期间本机监听端口保留，新进来的连接会被直接关闭。自动重连不弹任何询问：需要重新输入密码、确认主机密钥时停止并写明原因，手动启动即可。三次都失败也会停止，并弹出通知。
- **修改后**：编辑运行中规则的类型、主机、监听或目标，这条转发会按新设置重新启动；只改名称或自动开启不会。编辑它所经由的主机（地址、认证方式、凭据、跳板等）不影响运行中的转发，下次启动时才用新的设置。
- **删除主机**：删除主机（或包含它的分组）会连同经由它的转发规则一起删除，运行中的先停止，确认框里写明数量。
- **动态转发**支持 SOCKS5（无认证，`CONNECT`，IPv4、域名、IPv6）和 SOCKS4 / 4a。域名交给服务器解析。
- **监听地址**默认 `127.0.0.1`。填其他地址时，本地和动态转发会被同一网络中的其他设备使用；远程转发需要服务器的 `sshd_config` 设置 `GatewayPorts clientspecified` 或 `yes`，其他机器才连得上；默认是 `no`，这时转发照常运行、不报错，但只监听服务器自己的 `127.0.0.1`（和手写 `ssh -R` 一样）。对话框在填了非回环地址时会提示这一点。1024 以下的端口需要管理员（服务器上是 root）权限。不支持端口 0（由系统挑选端口）。

**尚未实现：规则排序。系统的「减少动态效果」设置目前不会关掉示意图的动画。**

## 凭据

点标题栏的凭据（钥匙）图标，左侧栏换成凭据列表。一条凭据是一套可以让多台主机共用的登录信息，包括名称、用户名和登录方式：

| 类型 | 保存什么 | 登录时 |
| --- | --- | --- |
| 密码 | 用户名和密码 | 用凭据保存的密码；没存或被拒绝时询问 |
| 密钥 | 用户名、私钥和口令 | 只用这把私钥；口令按私钥文件保存，用同一个文件的凭据共用 |
| SSH Agent | 用户名 | 只用 SSH Agent 中的密钥：macOS / Linux 上是 `SSH_AUTH_SOCK` 指向的 Agent，Windows 上是 OpenSSH Authentication Agent 服务 |

- **新建和编辑**：列表标题栏的「+」、空列表里的「新建凭据…」或空白处的右键菜单打开对话框；双击凭据、选中后回车或右键「编辑凭据…」编辑。密码和私钥口令存进系统钥匙串，数据库里只有名称、用户名、类型和私钥路径。
- **密钥从哪里来**：密钥凭据的「私钥」有三种来源。
  - **本机文件**：选一个私钥文件，ShellRS 复制一份进数据目录的 `keys/`，原文件只读这一次、从不改动。之后改了原文件（比如换了密钥）、连不上时，在这里重新选一次。升级前建好、只记了路径的凭据照旧用原来的文件。
  - **粘贴**：贴进 OpenSSH、PEM 或 PuTTY 格式的私钥。贴成公钥或认不出的内容时会说明原因。私钥加了口令时才显示口令栏。
  - **生成新密钥**：选 Ed25519（默认）或 RSA 4096，选中就生成；对话框里显示公钥，旁边可以复制。口令可留空；填了就用它加密私钥，口令存进钥匙串。生成的密钥以凭据名称作为注释。
  - 三种来源的私钥都由 ShellRS 存成数据目录下 `keys/` 里的文件（随机文件名，只有自己的账户能读），凭据引用这个文件，编辑时显示为「本机文件」和它的路径。之后再粘贴或生成会直接覆盖这个文件，已连接的主机不会因此重连；改成别的文件或别的类型、或删除凭据时，这个文件连同它的口令一起删除，对话框会先提示。用户自己的私钥文件 ShellRS 从不改动或删除。数据目录整个搬走后（便携版换了盘符，或把别处的数据拷了进来），凭据自动改指向新位置的同一个文件；钥匙串按路径记口令，所以加了口令的私钥会再问一次口令。
  - 空列表和空白处的右键菜单里另有「生成密钥…」，打开的是同一个对话框，已经选好「密钥 · 生成新密钥」。密钥凭据的右键菜单有「复制公钥」，用来把公钥加到服务器的 `~/.ssh/authorized_keys`。
- **主机跟着凭据变**：改凭据的用户名，所有使用它的主机的用户名一起变。已打开的标签不受影响，新开的标签才用新的设置；对话框里写明有几台主机在用。
- **删除**：右键「删除」。有主机在用时确认框写明数量和它们之后怎么登录：用密码凭据的主机改为「密码」，连接时询问；用密钥或 SSH Agent 凭据的主机改为「无密码」。用户名不变，密码和私钥不会复制过去。已经打开的连接不受影响，凭据的密码随凭据一起从钥匙串删除。
- **SSH Agent 凭据**连不上 Agent、Agent 里没有密钥或服务器不接受其中任何一把时，会直接说明原因，不会改为询问密码。「无密码」的主机也会尝试同一个 Agent，连不上时静默跳过，接着试默认私钥（Windows 上同样如此）。

**尚未实现：在主机对话框里直接新建凭据、凭据排序、自定义 SSH Agent 的套接字、把公钥自动装到主机上、导出 ShellRS 保存的私钥。**

## 同步

经一个文件夹、WebDAV 服务器或 S3 存储桶在几台电脑之间同步保存的数据：主机、分组、凭据、端口转发和命令片段，连同主机和代理的密码、凭据的密码、私钥口令和 `keys/` 里的私钥。文件夹可以是 iCloud 云盘、Dropbox、OneDrive 等网盘同步的文件夹，也可以在共享盘上；WebDAV 可以是坚果云、Nextcloud、群晖等支持 WebDAV 的网盘或服务器；S3 可以是 AWS S3，或 Cloudflare R2、MinIO、Backblaze B2、阿里云 OSS、腾讯云 COS 等兼容 S3 的对象存储。

- **开启**：「设置 › 云同步」里点「选择文件夹…」选一个文件夹，或点「连接 WebDAV…」填服务器的地址、用户名和密码。地址是服务器上放同步数据的文件夹（比如坚果云的 `https://dav.jianguoyun.com/dav/ShellRS`），不存在会自动建。坚果云要用网页「账户信息 › 安全选项」里生成的应用密码，Nextcloud 用「设置 › 安全」里的应用密码。「测试连接」在那里写一个小文件、读回来再删掉，看能不能读写。或点「连接 S3…」填服务地址、区域、存储桶、桶里的文件夹和访问密钥：区域留空是 us-east-1，Cloudflare R2 填 `auto`；MinIO 等自建的服务勾选「路径式地址」；桶要先在服务商那里建好，访问密钥给这个桶读写的权限就够了。WebDAV 密码和 S3 的 Secret Access Key 只存在系统钥匙串里，服务器或存储桶之后拒绝了它（比如应用密码或访问密钥被撤销），同步就停下来请你重新登录；设置页的「WebDAV 账号」「S3 访问密钥」也可以随时更改。那里还没有同步时创建：设一个同步密码（至少 12 个字符，也可以点「生成随机密码」），别的电脑加入时要输入它。同步密码忘了就无法找回，只能关掉同步、换个文件夹重新创建。那里已有同步时加入：输入它的同步密码，这台电脑上的数据和其他设备的合并，谁的都不删。
- **什么时候同步**：开启时、启动时、窗口切回前台时（每分钟最多一次）、改动后停下 5 秒、点「立即同步」时，以及退出前（最多等 3 秒）；不定时轮询。同一条记录在两台电脑上都改了，以后改的为准。状态写在「设置 › 云同步」里，出错时也只写在那里，不弹通知。
- **不同步的**：串口主机（串口号是这台电脑的）、临时连接和外部连接、「项目」里的本地终端和全部设置。主机的系统、右侧栏开着的工具、分组展开与否、转发是否随 ShellRS 开启也只记在这台电脑上。升级前只记了路径的私钥不同步，在凭据里重新选一次私钥文件就会同步。
- **加密**：数据在这台电脑上加密后才写进文件夹或服务器，那里每台设备一个文件，只有密文。同步密码只用来解开密钥，从不保存；密钥存在系统钥匙串里，所以没有钥匙串的电脑开不了同步。钥匙串被锁、读不出密码时，这一轮不动任何密码，不会当成删除。
- **设备**：「其他设备」列出同一个文件夹里的设备、它们的系统和版本、上次同步的时间。「移除…」删掉那台设备在文件夹里的文件，那台设备下次同步时会先问要不要重新加入。设备丢了，移除后再更换同步密码：数据密钥会一起换新，它即使知道旧密码，也读不了之后的数据。
- **更换同步密码**：数据密钥一起换新。别的设备下次同步时提示输入新密码，输入后照常同步，数据不用重新合并。
- **要你确认的**：一次同步要删除 10 条以上、又超过一半的记录时，同步先停下，通知和设置页都会提示，你确认后才删，选「取消」就一直等着。同步在别的设备上被重置、或这台电脑被移出时也一样，等你输入密码或重新加入。
- **关闭同步**：这台电脑上的数据保留不动，同步的密钥、WebDAV 密码或 S3 密钥和状态删除；可以勾选同时删除这台电脑在同步位置的文件。

**尚未实现：第一次加入时预览重复的主机，手机端。**

## 设置

侧栏最下方的「设置」按钮（或 ⌘,，其他平台 Ctrl+,）在中间区打开「设置」标签页；已经打开时切换到该标签，不会重复打开。设置页分两栏：左边是分类（外观、终端、关键字高亮、键盘快捷键、同步、应用、关于），上方可搜索，栏宽可拖动；右边是所选分类的设置。设置改动立即生效并保存在数据目录的 `settings.json` 里。

- **外观 → 常规 → 界面语言**：跟随系统、简体中文、English，默认跟随系统：系统语言是中文时用简体中文，其他语言用英文。改动立即生效，不用重启：窗口里的文字、已打开的标签和搜索框提示一起换成新的语言；已经写进终端的提示和已经弹出的通知保持原样。
- **外观 → 常规 → 应用外观**：深色、浅色、跟随系统，默认跟随系统；选「跟随系统」时随系统的深浅色切换。标题栏的主题按钮也会改写这一项。
- **外观 → 常规 → 界面字号**：12–20 像素，默认 16，Windows 上默认 14（正文和系统界面的字一样大）。界面的文字和间距随之缩放，改动立即生效；终端的字号在「终端 → 字体配置」里单独设置。在终端以外按 ⌘= / ⌘-（其他平台 Ctrl）每次调 2 像素，⌘0 回到默认，改的就是这一项。
- **外观 → 主题**：左栏是浅色主题，右栏是深色主题，各选一套：应用外观为浅色时用左栏选中的那套，深色时用右栏的；跟随系统时随系统一起切换，标题栏的主题按钮切换时也一样。默认只有终端按所选主题配色，界面保持中性的灰色调（深色是不刺眼的炭灰，不是纯黑）；打开上方的「界面跟随主题」，界面也按主题配色：侧栏、标签栏、对话框等用主题的底色和文字色，成功、警告、错误等状态用主题的绿、黄、红。每张卡片用该主题的颜色显示一段示例，选中的右上角有蓝色对勾。默认是 ShellRS Light 和 ShellRS Dark，与界面同色。内置浅色、深色各 10 套：浅色 ShellRS Light、Solarized Light、Tokyo Day、Catppuccin Latte、Flexoki Light、One Half Light、Gruvbox Light、Kanagawa Lotus、Rosé Pine Dawn、Everforest Light；深色 ShellRS Dark、Solarized Dark、Tokyo Night、Catppuccin Mocha、Flexoki Dark、One Half Dark、Gruvbox Dark、Kanagawa Wave、Dracula、Nord。同一主题的浅色版和深色版在两栏的同一行。改动立即作用于所有已打开的终端，字体和关键字高亮的预览也用当前主题；vim 等程序询问终端的背景色时，得到的是当前主题的颜色。**尚未实现：自定义主题、导入配色、按主机指定主题。**
- **终端 → 字体配置**：字体（只列出本机安装的等宽字体，默认是系统的等宽字体，macOS 上为 Menlo）、字号（10–28 像素，默认 13）、行高（字号的 1.0–2.0 倍，默认 1.54，即原来的 20 像素行高）。制表符（如 tmux 分屏的边线）和方块字符由 ShellRS 按格子自己画，不取自字体，任何字体和行高下都上下左右连成一片。改动立即作用于所有已打开的终端；在终端里按 ⌘= / ⌘-（其他平台 Ctrl）也能逐级调字号，⌘0 回到默认。下方的预览按终端的排法显示字母、数字、易混字符、符号、中文、制表符和一行命令。设置文件里的字体在本机没有安装时，使用默认字体。
- **终端 → 终端交互**：「选中复制」打开后，用鼠标选中文字、松开时就复制到系统剪贴板，不用再按 ⌘C；默认关闭，单击没选中文字时剪贴板不变。「右键行为」决定在终端里按右键做什么：显示菜单（默认）、粘贴（直接粘贴剪贴板，同 ⌘V）、无动作。选后两种时，菜单里的复制、粘贴、全选、查找、清屏仍可用快捷键，上传文件、下载文件、重新连接在标签的右键菜单里。「光标样式」可选方块（默认）、下划线或竖线；「光标闪烁」默认开启，关闭后光标常亮。程序自行指定的光标样式和闪烁状态仍按程序要求显示，程序恢复默认时使用这里的设置；软件渲染时始终不闪烁。改动立即作用于所有已打开的终端，并在下次启动时保留。
- **终端 → 侧栏功能**：两排图标，上面一排「显示在右侧栏」，下面一排「不显示」，各按右侧栏的顺序排列，图标下写着名称。点一下图标，或把它拖到另一排，就显示或隐藏这个工具；鼠标停在图标上显示它的用途。除了 GPU/NPU 和 Kubernetes 都默认显示（不是每台主机都有显卡或 kubectl）。这一组右上角的「恢复默认」只恢复这些工具，页面右上角的重置则连同整页一起恢复。改动立即生效：隐藏正在显示的工具时右侧栏收起。全部隐藏后右侧栏连同按钮都不出现，只能回到这里恢复。主机系统用不了的工具照旧不显示。「项目」只出现在本地终端旁，其余工具只出现在远程终端旁。
- **终端 → 本地终端**：「Shell」是新开或重新启动的本地终端运行的程序，写路径或命令，可以带参数（如 `/bin/zsh -l`、`pwsh.exe -NoLogo`）；路径里有空格就用引号括起来（Windows 只认双引号）。输入框右端的下拉列出本机装了的常用 shell（macOS / Linux 是 zsh、bash、sh、fish、nu、pwsh 里装了的，包括 Homebrew 装的；csh、ksh、dash 等不列，要用就「选择文件…」；Windows 是 PowerShell 7（装了的话）、Windows PowerShell 和 cmd.exe），旁边的「选择文件…」用系统的文件选择框挑一个程序。留空（默认）时自动检测系统默认的 shell：macOS / Linux 是用户的登录 shell，Windows 优先 PowerShell 7，其次系统自带的 Windows PowerShell，都没有才用 cmd.exe。只写一个 shell、不带参数时（如 `/bin/bash`、`zsh`），和默认一样按登录 shell 启动，会读 `~/.zprofile` 等登录配置；带了参数或不是 shell 的程序就照写的启动。已经在运行的本地终端不受影响，重新启动后生效。「保留终端内容」默认打开，见「项目」一节；关掉时会删除已经保留的全部内容。
- **关键字高亮**：总开关、预览和规则表，终端里按规则给文字上色、匹配时提醒，见「终端」一节。
- **键盘快捷键**：主要功能的快捷键，分通用、标签、终端三组，每行是功能名和它的按键。点按键进入「按下组合键」，按下新的组合就换上；Esc 或点别处放弃。行尾两个按钮：禁用（之后显示「无」，再点一下恢复默认）、恢复默认；页面上方的「重置」也能逐项恢复。改动立即生效，工具栏提示和右键菜单里显示的按键跟着变。
  - 组合键要带 ⌘、⌥ 或 ⌃（其他平台 Ctrl 或 Alt），或者是 F1–F12，也可以是 Shift 加 Insert、Delete、Home、End、PageUp、PageDown（如用 Shift+Insert 粘贴）；「切换到标签 1…9」按任意一个带修饰键的数字即可，九个一起换。
  - 已被同一处的另一个快捷键、或输入框等内置功能占用的组合会被拒绝，并提示被谁占用；想换就先改或禁用那一个。终端里的快捷键可以和通用快捷键同键，在终端里以前者为准（如 ⌘K 在终端里是清屏）。
  - 默认（macOS / 其他平台）：新建主机 ⌘N / Ctrl+N，新建分组 ⌘⇧N / Ctrl+Shift+N，打开设置 ⌘, / Ctrl+,，显示或隐藏侧栏 ⌘B / Ctrl+B，显示或隐藏右侧栏 ⌘⌥B / Ctrl+Alt+B，显示或隐藏撰写窗格 ⌘⇧E / Ctrl+Shift+E，最大化窗口和还原窗口 ⌃⌘↑ ⌃⌘↓ / 无（系统自带的 Win+↑、Win+↓ 就是），显示或隐藏 ShellRS（全局）无，聚焦搜索 ⌘K / Ctrl+K，放大、缩小界面和实际大小 ⌘= ⌘- ⌘0 / Ctrl+= Ctrl+- Ctrl+0，退出 ⌘Q / Ctrl+Q；新建本地终端 ⌘T / Ctrl+T，关闭标签 ⌘W / Ctrl+Shift+W，下一个标签 ⌘⇧] / Ctrl+Tab，上一个标签 ⌘⇧[ / Ctrl+Shift+Tab，切换到标签 1…9 ⌘1…⌘9 / Alt+1…9（9 是最后一个）；终端的复制、粘贴、全选、查找、查找下一个、查找上一个、清屏 ⌘C ⌘V ⌘A ⌘F ⌘G ⌘⇧G ⌘K / Ctrl+Shift+C、Ctrl+Shift+V、Ctrl+Shift+A、Ctrl+Shift+F、F3、Shift+F3、Ctrl+Shift+K，放大、缩小字号和默认字号 ⌘= ⌘- ⌘0 / Ctrl+= Ctrl+- Ctrl+0。标签切换在当前标签所在的那组标签里进行，首尾循环。⌘= / ⌘- / ⌘0 在终端里调终端字号（每次 1 像素，范围同「终端 › 字号」的 10–28，写进设置，下次启动保留），在终端外调整个界面的字号（每次 2 像素，范围同「外观 › 界面字号」的 12–20，写进设置，下次启动保留）。
  - 在终端里，只按 Ctrl 加一个字母的通用快捷键不起作用，这个键照常发给 shell，如 tmux 的 Ctrl+B、bash 删前一个词的 Ctrl+W；离开终端才起作用。所以在 Windows 和 Linux 的终端里，新建本地终端、显示或隐藏侧栏等要用按钮，或者改成 Ctrl+Shift 加字母；关闭标签默认就是 Ctrl+Shift+W（同 Windows Terminal），在终端里也能用。
  - 「显示或隐藏 ShellRS（全局）」在别的程序在前台时也能用：ShellRS 不在前台时调到前台，已在前台时隐藏（Windows、Linux 上是最小化）。默认没有按键，要自己设；这个键在所有程序里都会被它拿走，所以别选常用的组合（如 ⌘Space、切换输入法的 ⌃Space）。已被其他程序占用的组合会被拒绝，但 macOS 上不一定查得出来。不需要辅助功能权限。Linux 上只在 X11 下有效；Wayland 下可以在系统设置里给启动 ShellRS 的命令设一个快捷键，ShellRS 已在运行时再次启动只会把它调到前台。
  - macOS 上的 ⌘H、⌥⌘H、⌘M 同其他 Mac 应用，是菜单栏的「隐藏 ShellRS」「隐藏其他」「最小化」，不在这一页里，也不能设给别的功能。
  - Enter、方向键、Tab、Esc 这些固定键不在这里改。
- **应用 → 窗口**：「记住窗口大小」恢复上次的窗口大小和最大化状态，「记住窗口位置」把窗口放回上次所在的屏幕和位置，默认都打开，下次启动时生效。那块屏幕不在了、或窗口大半在屏幕外时，放在屏幕中间；窗口比屏幕大时缩到能放下。首次打开（或关了「记住窗口大小」）时屏幕放不下默认大小的，比如 150% 缩放的 1920×1080 笔记本，窗口最大化打开，还原后是屏幕能放下的大小。全屏不记，按退出全屏后的大小恢复。窗口的大小和位置随移动随时记在数据目录的 `window.json` 里。左右侧栏拖动后的宽度记在 `settings.json` 里，下次启动照旧；「侧栏宽度」的「恢复默认」把两边改回默认宽度（左 280、右 320 像素），页面右上角的重置也会。
- **关于**：「应用更新」一组：当前版本和检查更新、更新渠道、自动升级，见「下载与更新」；「隐私」一组的「发送匿名使用统计」，默认打开，见「隐私」；「ShellRS」一组的「官网」用浏览器打开本项目的 GitHub 页面。

### 应用锁

在「设置 › 应用 › 应用锁」点击「启用…」，输入两次至少 8 个字符的密码。启用后，每次启动先显示解锁页；默认在验证通过后才加载主机、恢复本地终端、启动自动连接和同步。Enter 提交密码，错误时留在解锁页，Escape 和工作区快捷键不能跳过验证。

启用后，同一分区可设置「多久未操作自动锁定」，单位为分钟，默认 0 表示不自动锁定。键盘、鼠标和滚动操作会重新计时，解锁后也重新计时；后台终端输出和传输进度不会延长时间。时长会保存在这台电脑的设置里，重启后仍生效。

同一分区可「立即锁定」「修改密码…」或「关闭…」。修改和关闭都要求当前应用锁密码。立即锁定只隐藏工作区，已建立的连接、传输和端口转发继续运行；解锁后回到原来的标签页。

应用锁是这台电脑上的访问保护，不加密数据库和本地文件，也不随主机同步。启用状态、随机盐和 Argon2id 校验值一起保存在系统钥匙串的 `shellrs` 服务、`app-lock` 账户下，不保存明文密码。该条目不随数据目录路径变化，删除本地配置文件不会解除应用锁。密码无法找回，请自行妥善保管。

启动时先在后台读取钥匙串；读取被拒绝、钥匙串不可用或记录损坏时，界面不开放，可在恢复钥匙串访问后点击「重试」。关闭应用锁也在钥匙串里写入明确的关闭状态。启用、修改或关闭保存失败时，原有应用锁设置保持不变。

## 从堡垒机打开（外部连接）

JumpServer 等堡垒机的本地客户端可以像调用 Xshell 一样调用 ShellRS 打开终端：把 ShellRS 设成 SSH 客户端，参数照 Xshell 的写法填。ShellRS 收到 `ssh://` 链接就打开一个终端标签连过去：

```sh
ShellRS ssh://用户[:密码]@地址[:端口]
ShellRS -url ssh://用户[:密码]@地址[:端口] -newtab 标签名
```

- 认得 Xshell 的 `-url`（链接）、`-newtab`（标签名，没给就用地址）和 `-newwin`（忽略：ShellRS 只有一个窗口），不分大小写；别的选项忽略。只支持 `ssh://`，端口默认 22。用户名和密码里的特殊字符可以按 URL 的规则转义（`@` 写成 `%40`）；用户名里本身带 `@` 也行，最后一个 `@` 后面才是地址。`ssh://` 链接同 Xshell，用户名和密码里不转义的 `/`、`?`、`#` 也照收，如 `ssh://账号@域名/目标地址/root/client:密码@堡垒机:端口`。
- **标签占满窗口**：打开外部连接时，左侧的主机列表自动收起（同 ⌘B），双击标签即可展开，macOS 上也可以按 ⌘B（其他平台的 Ctrl+B 在终端里发给 shell）。
- **外部连接，不保存**：不进主机列表、开始页的最近连接和数据库；它的终端标签都关掉后就没了。标签的菜单里没有「编辑主机…」，其余（复制会话、重新连接）和保存的主机一样。
- **只用一个通道**：很多堡垒机在同一条连接上又开一个通道时会结束整个会话。终端不探测主机系统（标签上显示名称的首字母），右侧栏只有「命令片段」，历史命令、tmux、Docker、系统服务、进程管理、网络连接、系统监控和 GPU/NPU 都要另开通道，这里不提供。
- 链接里的密码只留在内存里，不进钥匙串，重新连接时照样用它；没带密码时，服务器要密码就弹框问。第一次连到某台堡垒机要信任它的主机密钥，记在 ShellRS 自己的 `known_hosts` 里，下次不再问。
- ShellRS 已经在运行时，链接交给正在运行的那个打开，窗口调到前面，不会再起一个 ShellRS。链接有问题（不是 `ssh://`、没有用户名或地址、端口不对）时，ShellRS 弹通知说明原因。
- 堡垒机要调用的程序：
  - Windows：安装目录里的 `shellrs.exe`（默认 `%LOCALAPPDATA%\Programs\ShellRS\shellrs.exe`），便携版是便携版文件夹里的 `shellrs.exe`。
  - macOS：`/Applications/ShellRS.app/Contents/MacOS/shellrs`。不要用 `open -a ShellRS --args …`：ShellRS 已在运行时，系统会把参数丢掉。
  - Linux：AppImage 本身。
- 命令行参数里的密码在本机的进程列表里看得到，这是堡垒机这样传参本身的问题。

## 标签页

远程终端标签以主机系统徽章为图标：打开时用主机列表里的那个，终端连上后换成它自己探测到的；别的连接后来探测到的系统只更新主机列表。串口主机的终端标签菜单没有「上传文件…」「下载文件…」和「复制 IP」，多一项「发送 Break」：让线路保持断开状态约 0.3 秒，Cisco 等设备的密码恢复、Linux 的 SysRq 要用。Telnet 主机的标签菜单也有「发送 Break」（发送 Telnet 的 Break）和「复制 IP」，没有「上传文件…」「下载文件…」。右键标签可重命名（仅本次运行有效，留空恢复为主机的名称，用于区分同一台主机的多个连接）、复制会话、上传文件、下载文件、复制 IP / 主机名、重新连接、编辑主机，以及关闭当前、左侧、右侧、其他或全部标签。SSH 主机的终端标签栏右侧有「上传文件…」「下载文件…」和「重新连接」按钮（见「文件传输」）；本地终端标签是「重新启动」加关闭命令。「复制会话」打开独立的新终端标签，继承原标签的名称（包括重命名后的名称）和连接信息。SSH 终端已获知工作目录时，新连接成功后会自动进入原目录；未获知目录时按正常登录目录开始。目录仅在复制后的首次成功连接时恢复。标签栏右侧「…」按钮的菜单与当前标签的右键菜单相同。双击任一标签的标题可隐藏或显示左侧的侧栏（同 ⌘B 和标题栏的按钮）；用鼠标中键点标签的标题关闭这个标签，同点 ×；双击标签右边的空白处新建一个本地终端。标签多到放不下时，在标签栏上转动鼠标滚轮可左右滚动标签。远程终端运行时，标签栏右侧显示这条 SSH 连接的往返延迟，每 5 秒更新一次：低于 100 ms 为绿色，100–200 ms 为黄色，高于 200 ms 或超时为红色。文件传输进行中也照常测量，读数会随传输占满带宽而升高。

### 撰写窗格

先把命令写好、改好再发到终端时用，可以写多行。⌘⇧E（其他平台 Ctrl+Shift+E）或终端右键菜单的「撰写窗格」显示或隐藏它。它在终端下方、左右侧栏之间，整个窗口只有一个，拖动上边缘可以调高度。

- **发给谁**：在前的那个终端，本地、远程都行，和右侧栏、状态栏跟着的是同一个（分屏时是最近一次切到或点进去的终端）。标题里写着发给谁，如「撰写窗格 · web-01」。屏幕上没有终端时它隐藏，有了再出现。
- **发送**：回车或点「发送」执行写好的命令，Shift+Enter 换行。命令原样发出，接在终端里已经打的内容后面，不先清掉那一行。多行命令在终端支持括号粘贴时（zsh、fish，bash 5.1 起默认）整段粘贴后执行，否则逐行执行。发出后撰写窗格清空，焦点留在这里；空着按回车，就是在终端里按一下回车。正在运行全屏程序（vim、top 等）的终端收不到命令，通知里会写明。
- **历史**：在第一行按 ↑ 回到之前发过的命令，像在终端里一样往回翻；在最后一行按 ↓ 往新的翻，翻过最新的一条回到正在写的内容。多行命令算一条，往回翻到它时光标在第一行，再按 ↑ 接着往回；在其他行按 ↑ ↓ 照常移动光标。翻到的命令可以改了再发，改动在下次发送前一直留着。空的、和上一条相同的、以空格开头的命令不记（同 bash 的 `HISTCONTROL=ignoreboth`），用「片段」发的也不记。最多记最近 500 条，以明文存在数据目录的 `compose-history.json` 里，下次启动还在，不同步。
- 「片段」选一条命令片段发过去，按片段的「点击时自动执行」决定是直接执行还是只放进输入行。「Ctrl+C」向终端发送 Ctrl+C。
- 显示还是隐藏，下次启动也记得；高度和没发出的内容记到退出为止。

### 命令广播

在几台主机上同时执行同样的命令时用。点标签栏最左边（隐藏侧栏按钮旁边）的「命令广播」，远程终端和本地终端标签的图标前面多出复选框，默认都不勾选；图标照旧，仍能看出终端是否在线。只有已连接的终端能勾选。

- 勾选两个以上时，这些终端按勾选的顺序自动排成分屏：两个左右并排，三四个排成两行两列，更多的照此类推。下方出现撰写窗格（原来就开着的照旧），改为发给全部勾选的终端。之后再勾选一个会重新排一次；取消勾选只是让它退出广播，布局不变。
- **撰写窗格**：广播时它就是命令栏，标题写着「勾选的 N 个终端」。回车或点「发送到全部」，在每个勾选的终端里执行；命令原样发出，不先清掉那一行（同 Xshell、SecureCRT 的发送到全部会话）。「片段」和「Ctrl+C」也发给全部终端，还多了「同步按键」开关。正在运行全屏程序的终端收不到命令，通知里写明是哪几个。广播期间撰写窗格不能隐藏，⌘⇧E 只把焦点移到这里。
- **同步按键**：默认关闭。打开后，在任一勾选的终端里打字、粘贴，也会同时发给其他勾选的终端，各终端按自己的模式处理方向键和括号粘贴，在 vim 这类全屏程序里也能用。打字输入的密码也会一起发过去。
- 查找框、认证弹框、鼠标操作、终端的协议回复，以及历史命令和命令片段侧栏发起的命令都不广播。广播的 Ctrl+C 会取消另一个终端里正在进行的 ZMODEM 传输；同步按键时，你的按键会让另一个 Telnet 终端停止自动登录。
- 关闭、断开或重连的终端自动退出广播，重连后要重新勾选，新开的终端也不会自动加入。点撰写窗格右上角的 × 或再点一次「命令广播」结束广播：复选框消失，撰写窗格回到广播前的样子（原来没开的就隐藏），分屏保留，可以拖回去。广播状态不保存。

## 终端

远程终端标签按各自的连接显示状态：已连接时图标是彩色的；连接中和断开时图标变成灰色，标签上的名称也变灰。鼠标移到图标上可看到文字说明（如「Ubuntu · 未连接」）。远程终端连接失败、退出、手动断开或取消认证后，显示「按 Enter 重新连接，按 Space 关闭标签页」：聚焦终端后按无修饰键的 Enter，在原标签按打开时的配置重连；按 Space 关闭这个标签（同点标签上的 ×）。按住按键、粘贴、查找或认证输入框不会触发。本地终端仍使用重新启动。

右键终端内容区可复制、粘贴、全选、查找、清屏，以及显示或隐藏撰写窗格；远程终端在「复制」下面另有「复制 IP」（地址是域名时叫「复制主机名」）和「复制 ID」，菜单最后还有上传文件、下载文件、重新连接和断开连接。「设置 › 终端 › 终端交互」可以把右键改成直接粘贴或不做任何事，也可以打开「选中复制」。断开连接只断开这一个标签，标签保留，可随时重新连接，同一台主机的其他标签不受影响。

- **主机密钥**：第一次连接某台主机时要确认它的主机密钥（「信任并连接」），记在 ShellRS 自己的 `known_hosts` 里，之后不再问。服务器的密钥和记下的不一致时（重装了系统、换了密钥，也可能是有人冒充），弹框列出记下的和现在的指纹：「更新并连接」删掉这台主机记下的旧密钥、换成现在的再继续连接；「取消」不连接。测试连接和端口转发的自动重连遇到这种情况只报错、不询问，在 ShellRS 里连接一次这台主机更新即可。
- **回滚历史**：每个终端保留最近 10000 行。用滚轮或触控板往上翻看，这时右侧出现滚动条（和应用里其他列表一样，按系统的「显示滚动条」设置），可以拖动，点轨道直接跳到那个位置。vim、less、top 这类全屏程序没有回滚历史，不显示滚动条。
- **全选**（⌘A，其他平台 Ctrl+Shift+A）：选中回滚历史和屏幕上的全部文字，前后的空行不算，再按 ⌘C（其他平台 Ctrl+Shift+C）复制；打开了「选中复制」时直接复制到剪贴板。vim、less 这类全屏程序运行时只选中当前屏幕。
- **查找**（⌘F，其他平台 Ctrl+Shift+F）：在终端右上角打开查找条，按字面量搜索屏幕和回滚历史。查询全为小写时不区分大小写，含大写字母时区分。所有匹配高亮显示，当前项颜色更深，查找条显示「当前项/总数」。回车或 ⌘G（F3）跳到下一项（更新的输出），Shift+回车或 ⌘⇧G（Shift+F3）跳到上一项（更早的输出），到头后循环。Esc 关闭。打开时如有选中文字，会作为查询词。
- **清屏**（⌘K，其他平台 Ctrl+Shift+K；焦点不在终端时 ⌘K 仍是聚焦侧栏的搜索框）：清掉屏幕和回滚历史，只留下光标所在的提示符行，包括已输入但未回车的内容。清屏只在本地进行，不向服务器发送任何内容。vim、top 等全屏程序运行时不可用。
- **链接**：输出里的 `http://`、`https://` 地址，以及程序明确标出的链接（如 `ls --hyperlink`、gcc 的报错），显示为带下划线的蓝色。按住 ⌘（其他平台 Ctrl）单击，用系统浏览器打开；不按时单击照旧是选择文字。鼠标在链接上停一会儿会显示它真正的地址：程序标出的链接，显示的文字可以和地址不同。地址末尾的句号、逗号和不成对的右括号不算在内；被折成两行的长地址仍是一个链接。其他协议（如 `file://`）不当作链接。
- **鼠标**：vim（`:set mouse=a`）、htop、tmux（`set -g mouse on`）、mc 这类程序要求鼠标时，单击、拖动和滚轮都交给程序。按住 Shift 拖动仍是选择文字，按住 Shift 滚动仍是翻看回滚历史；右键从不交给程序，按「右键行为」的设置处理。
- **通知**：程序可以请求通知（OSC 9，或 OSC 777 的 `notify;标题;正文`），终端响铃时也会提醒。ShellRS 不在前台时发系统通知（macOS 第一次会询问是否允许），点通知回到那个终端；ShellRS 在前台但终端在别的标签时，在窗口右上角提示，点一下切过去。程序请求的通知即使终端就在眼前也会提示；响铃只在看不见那个终端时提醒（Tab 补全等也会响铃；分屏里显示着的终端也算看得见）。通知标题是标签名，看得出是哪台主机发的。同一终端的程序通知 2 秒内、响铃 10 秒内只提醒一次。设置 › 终端 › 通知可以分别关掉。命令跑完想被提醒，可以在后面加上 `; printf '\e]9;完成\a'` 或 `; tput bel`；Claude Code 等命令行工具需要你处理时也会这样提醒。
- **关键字高亮**：设置 › 关键字高亮 里的规则把匹配的文字按规则的颜色显示在所有终端里，回滚历史里的也一样。只改显示：服务器的输出不变，复制出的文字也不变；窗口缩放、长行折行后照样匹配，被折成两行的词两段都上色。这个功能默认关闭，打开页面上方的「启用关键字高亮」后才生效，关掉它就一次停用全部规则；「预览」用当前终端的字体和配色显示一段示例输出，规则改动立即反映在预览和已打开的终端里。规则表一行一条，直接在表里改：「启用」、「正则表达式」（区分大小写，开头加 `(?i)` 不区分）、「备注」、颜色（点色块用取色器，或在旁边填 `#rrggbb`）、「通知」，行尾的垃圾桶删除这一条。正则写错时在框下方提示，这条规则暂不生效。规则从上到下应用，重叠处前面的规则优先；按住行首的把手拖动可调整顺序。初始有三条示例：`ERROR` 红色、`WARN` 琥珀色、IPv4 地址蓝色，都已启用、不通知，打开总开关就能看到效果，可以修改或删除。勾选「通知」的规则在看不到那个终端时提醒，和响铃一样：ShellRS 不在前台时发系统通知，终端在别的标签时在窗口右上角提示；标题是「标签名：备注」（没填备注时用正则），正文是匹配的那一行。只检查换了行的新输出，同一终端 10 秒内只提醒一次，反复重画的同一行 5 分钟内只提醒一次。vim、less、top、tmux 这类全屏程序里不高亮，也不提醒。**尚未实现：按主机区分规则、加粗等文字样式、用键盘调整顺序。**
- **远程复制**：远程程序用 OSC 52 复制的内容（如 tmux 的 `set -g set-clipboard on`、vim 的 OSC 52 插件）直接进本机剪贴板。远程程序读不了本机剪贴板。
- **Shift+Enter 换行**：Claude Code 等命令行工具会询问终端能否区分按键（kitty 键盘协议），ShellRS 照实回答，并在它们运行时按协议发送按键，Shift+Enter 就能在里面换行（Option+Enter，其他平台 Alt+Enter，照旧也行）；远程终端里运行也一样。普通 shell 里 Shift+Enter 仍等于回车。
- **本地终端的标签名**：显示 shell 设的标题；shell 没设时，「项目」里的终端显示上次的标题或它在那里的名字，其余的显示「本地终端 1」这样的名字。在「项目」里手动起过名字的终端固定显示那个名字。zsh、bash 常把标题设成「用户@主机:目录」，是本机的、又超过 30 个字符时只显示目录的名字（如 `go-dock`）；短的标题，以及在本地终端里 ssh 到别的机器后的标题，照原样显示。程序运行时显示它自己设的标题，比如运行 Claude Code 时是「✳ Claude Code」。标签名太长时末尾显示省略号。
- **ZMODEM 传文件**：在终端里运行 `rz` 或 `sz 文件…`（服务器上要装 lrzsz，如 `apt install lrzsz`、`yum install lrzsz`），ShellRS 自动接上。SSH、Telnet、串口终端都能用，只给一个 shell 的堡垒机上也行；本地终端里 ssh 到别处再运行也行。
  - `rz`：弹出选择框，选要上传的文件（可多选）。`sz`：弹出选择框，选保存到哪个文件夹，每次都问。在选择框里取消，就终止远端的 rz / sz。
  - 拖放上传：把文件从访达（资源管理器）拖到远程终端上，ShellRS 替你输入 `rz` 并回车，直接上传这些文件，不再弹框。拖进来的文件夹会被跳过，文件夹请用标签栏右侧的「上传文件…」。
  - 传输时终端里有一行进度（文件名、百分比、大小、速度），每个文件传完留一行结果。按 Ctrl+C 取消，其他按键这时不起作用。
  - 下载不覆盖已有的文件，同名时存成「名称 (1)」；没收完的文件会删掉。lrzsz 的 `rz` 默认也不覆盖服务器上已有的同名文件，这时显示「已跳过」，要覆盖请用 `rz -y`。
  - 取消下载后，lrzsz 的 `sz` 还会再发一会儿才停，ShellRS 不显示这些数据，等它停下再显示提示符；再按一次 Ctrl+C 就不再等。
  - 单个文件最大 4 GB，这是 ZMODEM 协议的上限。在 tmux、screen 里用不了，它们会改动传输的数据。Telnet 上要求服务器按 Telnet 的规矩处理回车（一般都是这样）。
- **没有显卡时**：在没开 3D 加速的虚拟机里，界面由 CPU 渲染（「关于」页版本号的悬停提示里写着「软件渲染」），每画一帧都占 CPU。这时 ShellRS 少画几帧：终端输出最多每 50 毫秒画一次（停了一会儿后的第一次照样立即画，打字不受影响），光标不闪，没有动画。虚拟机能开 3D 加速的话建议打开。

## 右侧栏

当前标签是远程终端时，窗口最右边有一列工具按钮：命令片段、历史命令、tmux、Docker、Kubernetes、系统服务、进程管理、网络连接、系统监控和 GPU/NPU，其中 Kubernetes 和 GPU/NPU 默认不显示；显示哪些工具在「设置 › 终端 › 侧栏功能」里选。点一个就在右侧打开这个工具，再点一次收起；⌘⌥B（其他平台 Ctrl+Alt+B）显示或隐藏右侧栏。拖动右侧栏的左边缘可以调整宽度，默认 320 像素、最窄 220 像素，下次启动照旧。当前标签是本地终端时，这一列只有「项目」（见下面的「项目」）和「命令片段」两个按钮。右侧栏只跟着终端出现，切到设置时连同按钮一起隐藏。开没开、开的是哪个工具按主机记住：切到一台主机的终端时，右侧栏恢复成这台主机上次的样子，没打开过的主机是收起的；保存的主机下次启动 ShellRS 也记得，临时连接只记到退出。比如在 web-01 上打开「系统监控」，以后连 web-01 都自动打开「系统监控」，连其他主机则不会。本地终端共用一份，下次启动也记得。把标签拖成分屏后，右侧栏不隐藏：它对应最近一次切到或点进去的终端（远程或本地都算），屏幕上一个终端都没有时才隐藏；标题里写着它对应哪台主机（如「系统监控 · web-01」），状态栏也跟着点进去的那一半。已知不是 Linux 的主机（macOS、Windows、BSD）不显示系统服务、进程管理、网络连接、系统监控和 GPU/NPU 的图标；历史命令、tmux、Docker 和 Kubernetes 除了 Windows 主机都有（Mac 上装了 tmux、Docker Desktop 也能用）。Telnet 和串口终端只有命令片段：其余工具要在终端旁边另执行命令，Telnet 和串口做不到。

**命令片段**保存常用的命令，所有主机和本地终端共用，远程终端和本地终端旁都有。点顶部的加号新建片段：名称、分类和命令，命令可以有多行。列表像主机列表一样：分类可以任意嵌套，每一层先列分类、再列片段，没有分类的片段放在最外层、分类后面；每行只显示名称，鼠标移到片段上时，旁边显示它的命令。点分类折叠或展开（不记住，下次启动都展开），右键分类可以在里面新建片段或子分类、重命名或删除分类（里面的子分类和片段会一起删除，确认时写明个数）；顶部的文件夹按钮新建最外层的分类，重命名分类时也可以选「上级分类」把它移到别的分类里。同一层里分类不能重名，不同层可以。

拖动可以调整顺序：把片段拖到另一个片段的上半部或下半部，放在它前面或后面（也就到了它所在的分类）；拖到分类上，放进这个分类的最后；把分类拖到另一个分类的上下边缘调整先后，拖到中间就放进去成为子分类；拖到空白处移到最外层的最后。分类不能拖进它自己或它的子分类里。搜索时不能拖动。新建的片段和分类排在所在那一层的最后；以前版本建的、没拖过的仍按名称排列。顺序和嵌套跟着云同步走；ShellRS 0.1.17 及更早的版本收到时把分类都列在最外层，但不会改掉别处的顺序和嵌套。可以按名称或命令搜索，输入几个词时列出同时包含这些词的片段，连同它们所在的分类。

点一个片段就在终端里执行它的命令（片段默认「点击时自动执行」）。鼠标移到片段上时，右边会显示点它会怎样：闪电表示点击就执行，▶ 表示点击只输入。在片段对话框里取消勾选「点击时自动执行」，点它就只把命令放进终端的输入行（替换掉已经输入的内容），可以修改后回车。点右边的闪电或 ▶ 总是直接执行；右键还可以输入到终端、复制命令、编辑和删除。终端里正在运行 vim、less 这类全屏程序时不会输入。Windows 主机上，以及 Windows 电脑的本地终端里，不会替换已经输入的内容，命令接在后面输入。

**历史命令**列出远程主机上 bash 的历史命令（`~/.bash_history`），最近执行的在最前，同一条命令只列一次，下面写着执行过几次；bash 记录了时间（设置了 `HISTTIMEFORMAT`）时还写明最近一次是什么时候，多行的命令也能认出来。可以搜索，输入几个词时列出同时包含这些词的命令，不分大小写。点一条命令把它放进终端的输入行（替换掉已经输入的内容，不执行），可以修改后回车；点右边的执行按钮直接执行；右键还可以复制。终端里正在运行 vim、less 这类全屏程序时不会输入。

bash 在 shell 退出时才把这次执行的命令写进历史文件，所以当前终端里刚执行的命令要等它退出后才会出现。列表在打开历史命令或切换终端时读取，之后点刷新按钮才重新读取；历史文件很长时只读最后 512 KB。

**tmux** 列出远程主机上的 tmux 会话：名称、连着几个终端（「已连接 N」或「未连接」）和会话开始时的目录，当前终端所在的会话标着「当前」。顶部写着 tmux 的版本；主机没有装 tmux 时写「远端未安装 tmux」，按钮都不能用。「新建」先问名称（留空由 tmux 编号；只能用字母、数字、- 和 _），然后让当前终端进入这个新会话；「退出当前」让终端退出所在的会话，会话在后台继续运行。每个会话右边是「连接」（让当前终端进入这个会话）、「重命名」和「结束会话」（先确认，会话里运行的程序都会被结束）。

当前终端不在 tmux 里时，连接和新建是往终端里输入并执行 `tmux attach -t 名称` 或 `tmux new -s 名称`（同历史命令，替换掉已经输入的内容；终端里正在运行 vim 这类全屏程序时不输入）。终端已经在 tmux 里时，键盘输入会交给 tmux 窗格里的程序，所以改为在终端的连接上另外通知 tmux 把这个终端切过去，不往终端里输入。ShellRS 从这条 SSH 连接的 sshd 找到终端用的 tty，再和 tmux 的客户端对照，判断终端在不在 tmux 里、在哪个会话；找不到时（比如服务器上没有 `ps`）当作不在 tmux 里。只列连接用户自己的会话：在终端里 `sudo -i` 后开的 tmux 会话不在这里。列表在打开 tmux 或切换终端时读取，连接、新建、重命名、结束、退出之后自动重读，其余时候点刷新按钮。

**Docker** 顶部是 Docker 和 Compose 的版本，下面「容器」「卷」「镜像」「网络」四个标签页带数量。「容器」页里，同一个 compose 项目的容器归在项目卡片下（项目名、运行中 / 总数、项目目录），点项目那一行折叠或展开，只有一个容器、而且它在运行的项目默认展开，有多个容器的项目默认折叠；不属于任何项目的在「独立容器」下。每个项目和容器右边有「停止」（或「启动」）和「重启」，项目的按钮作用于它所有的容器；点容器或它的「…」打开详情：「详情」页是名称、ID、镜像、创建时间、入口、命令、端口映射、挂载、环境变量和标签，「日志」页是容器最近 200 行输出；底部可以启动、停止、重启，已停止的容器还可以删除。「卷」「镜像」「网络」页列出各自的名称和基本信息，标出是否有容器在用；没有容器在用的可以点右边的删除按钮删除（Docker 自带的 bridge、host、none 网络不能删）。点卡片打开详情：卷是驱动、挂载点、创建时间、使用它的容器、选项和标签；镜像是完整 ID、标签、摘要、创建时间、大小、平台、层数、使用它的容器、运行配置（入口、命令、工作目录、用户、暴露端口）、环境变量和标签；网络是驱动、范围、IPv6、子网和网关、连在上面的容器及其地址、选项和标签。详情底部也可以删除。

停止、重启和删除都会先确认，启动直接执行，结果以通知显示，之后列表重新读取。不是以 root 登录、也不在 docker 组里时，通过免密码的 sudo 执行。列表在打开 Docker 或切换终端时读取，之后点刷新按钮才重新读取。主机没有安装 Docker 或 Docker 没有运行时会写明。

**系统服务**列出远程主机上的 systemd 服务（不含模板），分成「自定义服务」（unit 文件在 `/etc/systemd/system`，也就是管理员自己加的）和「系统服务」两组。顶部是 systemd 版本和整机状态（有服务失败时是「降级运行」）；「全部」「运行中」「已停止」「失败」四个标签页带数量，也可以按服务名或描述搜索。每个服务一张卡片：状态圆点、名称、描述、运行状态和开机启动状态；运行中的服务右边有「停止」「重启」，没运行的有「启动」，点「…」或卡片打开详情。详情的「状态」页是加载状态、运行状态、开机启动、主进程 PID、内存、任务数、重启次数、退出状态、启动和停止时间、unit 文件；「日志」页是这个服务在 journal 里最近 200 行。详情底部和右键菜单里同样可以启动、停止、重启，以及启用或禁用开机启动。

停止和重启会先确认（停止 SSH 服务时会特别说明），启动和开机启动的设置直接执行，结果以通知显示，之后列表重新读取。这些操作需要 root 权限：不是以 root 登录时通过免密码的 sudo 执行，sudo 需要密码时会提示需要 root 权限。列表在打开系统服务或切换终端时读取，之后点刷新按钮才重新读取。没有使用 systemd 的主机会写明暂不支持。

**进程管理**列出远程 Linux 主机上的进程（不含内核线程），每个一张卡片：状态圆点（绿色运行中、灰色休眠、黄色等待 I/O 或已暂停、红色僵尸进程，鼠标停上去显示状态）、进程名、PID、用户、启动时间（按本机时区），以及内存用量和占物理内存的比例、CPU 占用。CPU 占用和 `top` 的算法一样，按一个核计：占满两个核是 200%；它要两次读数才算得出，所以刚打开时先显示「—」，2 秒后出现。默认按内存从多到少排列，点「CPU」改按 CPU 排列，再点一次同一个按钮反过来排；可以按进程名、PID 或用户搜索，右边的数字是当前列出的个数。每 15 秒刷新一次，只在进程管理显示时读取，点右上角的刷新按钮立即读取。

点一个进程打开它的详情：PID、父进程、用户、状态（括号里是 `ps` 的状态字母，如 `Ssl`）、启动时间、运行时长、终端、优先级、Nice、CPU 使用率、累计 CPU 时间、常驻内存、虚拟内存、线程数、直接子进程数和全部后代进程数，下面是完整的命令行（打开详情时读取，可「复制命令」）。底部有「复制 PID」「结束进程」「强制结束」。

右键一个进程可以「查看详情」「结束进程…」（发送 SIGTERM，进程可以先做完收尾再退出）或「强制结束进程…」（发送 SIGKILL，立即终止）；从详情里结束也一样，都会先确认。结果以通知显示，1 秒后列表重新读取。不是以 root 登录时只能结束自己的进程。进程超过 2500 个时只列出前 2500 个，列表顶部会写明。

**网络连接**列出远程 Linux 主机上所有的 TCP、UDP 连接和监听端口，每条一张卡片：协议、状态、本地和远端地址，占用它的进程和 PID，以及所属用户。右上角写明这是「监听端口」「入站连接」（连到本机监听的端口）还是「出站连接」。顶部是总数、监听端口数和已连接数；可以按地址、端口、状态、PID、进程名或用户搜索，也可以按协议和状态筛选。监听的排在最前，然后是已连接的，TIME_WAIT 等正在关闭的排在最后；同一个端口被多个进程共同监听（如 nginx 的多个 worker）时合成一张卡片。

列表在打开网络连接或切换终端时读取一次，之后不会自己变化，点右上角的刷新按钮重新读取。数据通过这个终端已有的 SSH 连接读取，不需要再次登录，用的是主机上的 `ss` 命令；没有 `ss` 的主机（如 BusyBox）改为读取 `/proc/net`，这时看不到进程；不是以 root 登录时只能看到自己的进程。这两种情况列表顶部都会写明。连接超过 3000 条时只列出前 3000 条（监听端口总在其中），总数仍然准确。

**系统监控**显示远程 Linux 主机的：

- **系统**：主机名、架构、发行版、运行时长（如「32 天 23:40:26」）。
- **CPU**：型号、核数和平均使用率；多核时下面每核一根小竖条，鼠标停在竖条上显示这个核的编号和使用率。默认只显示一行，核多到一行放不下时点右上角的「N 核」展开全部。
- **内存**：物理内存的使用率和用量；有交换空间时另有一行。
- **网络**：主网卡（默认路由所在的网卡）的上传、下载速率；有多块网卡时点右上角的「N 个网卡」展开全部（不列回环网卡和从没收发过数据的网卡）。
- **磁盘**：每个本地挂载点的占用（不含 tmpfs 等内存文件系统和系统目录下的挂载）。

数据通过这个终端已有的 SSH 连接读取，不需要再次登录，也不安装任何东西；每 2 秒刷新一次（磁盘每 30 秒一次），只在系统监控显示时读取。每次刷新只读取几个系统文件，除了执行它的 shell 不在服务器上启动其他进程。使用率达到 70% 显示为黄色，达到 90% 显示为红色。终端未连接时显示提示；还没识别出系统的主机如果不是 Linux，会写明暂不支持。

**GPU/NPU** 给 AI 主机的显卡运维用，显示远程 Linux 主机上的 NVIDIA GPU（读 `nvidia-smi`）和华为昇腾 NPU（读 `npu-smi info`）。它默认不显示，要先在「设置 › 终端 › 侧栏功能」里打开。按 8 卡的机器设计：

- **汇总**：型号和驱动版本，设备数和主机已运行的时长，以及所有设备的平均利用率、显存（占用比例，下面是已用 / 总量）、最高温度和总功耗。
- **设备**：每张卡三行。第一行是编号（GPU 0、NPU 3；一张卡有多个芯片时每个芯片单列，写成 NPU 0.1）、型号、温度和功耗，下面两行是利用率和显存的条，一样长，方便对比。点一张卡展开详情：型号、UUID、总线 ID、性能状态、功耗和上限、风扇（有读数时）和健康状态；右上角的「全部展开」「全部收起」一次展开或收起所有卡。只有一张卡时默认展开。
- **计算进程**：正在用卡计算的进程，按卡号排列，同一张卡上显存占得多的在前；每个写明命令行、显存、卡号、PID 和用户。`ps` 看不到的进程（如别的 PID 命名空间里的）只有程序名。右键可以「结束进程…」或「强制结束进程…」，同进程管理，都先确认。

读不到的指标显示「—」，不当作 0。利用率和显存不按占用变色：训练时跑满、推理服务预先占满显存都是正常状态。温度达到 80 °C 显示为黄色，90 °C 显示为红色；健康状态不正常（NVIDIA 有 ECC 不可纠正错误，昇腾的 Health 不是 OK）时编号旁有黄点或红点，鼠标停上去显示原因。`nvidia-smi`、`npu-smi` 出错时（卡掉了、驱动没加载、权限不够）原样显示它们的报错。

数据通过这个终端已有的 SSH 连接读取，不需要再次登录，也不安装任何东西；每 2 秒刷新一次（上一次读完才开始计时，`npu-smi` 慢时自动放慢），运行时长也随之更新，只在 GPU/NPU 显示时读取。每个工具最多等 3 秒，不回答就停掉它，自动读取也随之停止，点刷新按钮再读：卡出故障时 `nvidia-smi` 可能卡在驱动里，一直重试会在服务器上堆积进程。主机上两个工具都没有时会写明。**尚未支持：AMD、海光 DCU、寒武纪等其他厂商。**

### Kubernetes

右侧栏的 Kubernetes 使用当前 SSH 主机上的 `kubectl` 和 kubeconfig，通过终端自己的连接读取，不额外登录。主机需要能运行 POSIX `sh`、已安装 kubectl、有可用的当前 context，并具备集群查询权限；Windows 主机和只允许一个通道的外部连接不显示此工具。它默认不显示，在「设置 › 终端 › 侧栏功能」里打开；关掉后入口隐藏，列表、日志和性能都停止读取。

1. 在远程终端右侧打开 Kubernetes，选择集群（context）。列表读取该集群的所有 namespace，默认显示“全部命名空间”，可以选择一个命名空间过滤。
2. 选择资源类型：Pod、Deployment、StatefulSet、DaemonSet、ReplicaSet、Service、Ingress、Job、CronJob、PVC。搜索按名称、命名空间、状态或标签过滤当前列表。
3. 点击资源名称查看状态、重点属性和带语法高亮的完整 YAML。次要属性可展开查看；详情字段可选择文字后用系统快捷键复制，右键可复制完整字段，也可使用“复制概要”。工作负载和 Service 有 Pod 选择器时，可点击关联 Pod 继续查看容器和日志。
4. Pod 的“日志”页可以选择普通、初始化或临时容器，选择最近 100–10000 行和最近 5 分钟至 24 小时；“上一次容器”读取所选容器上一次终止前的日志。检索区分大小写，可启用正则表达式，显示匹配行数；检索仅针对已读取的日志，每次最多 512 KB。
5. “生成命令”可以复制资源状态与事件、YAML、容器日志、实时跟踪日志、进入容器（`/bin/sh`）的命令。命令显式绑定 context、命名空间、资源和容器，可粘贴到对应 SSH 主机的终端执行。
6. 列表操作菜单和详情顶部提供编辑、重启、删除。Deployment、StatefulSet、DaemonSet 支持按更新策略重启，受支持控制器管理的运行中 Pod 通过重建重启；ConfigMap 支持编辑和删除。YAML 默认只读，进入编辑后可用保存按钮或 Ctrl+S / ⌘S 提交。保存、重启、删除都必须二次确认，确认框显示目标集群、资源和影响；取消不会写入，保存失败或版本冲突会保留草稿。

节点和 Pod 的“性能”页复用系统监控的 CPU、内存仪表与动画，每 10 秒刷新；节点磁盘用量每 30 秒刷新。只在查看性能页时读取，查询失败会延长重试间隔；缺少指标权限或服务时显示原因。

日志按时间戳、级别和 JSON 字段高亮，可复制单行或检索结果。“实时预览（2 秒）”串行刷新最新读取窗口，缓冲区最多 512 KB / 10000 行；超长行仅预览前 16 KB，检索与复制仍使用缓冲内完整内容。可关闭自动滚动以阅读旧行；离开日志页、关闭详情或查询失败时停止刷新。连续跟踪可使用生成的 `--follow` 命令。

查询不会切换 kubeconfig 的当前 context；编辑、重启和删除需要对应的 RBAC 写入权限，并在二次确认后才修改集群。列表在打开、切换 SSH 终端、改变查询范围、在这里修改资源之后和点击刷新时读取，不自己刷新。RBAC 权限不足、kubectl 不可用、API 失败或数据超过传输限制都会显示错误；读取 namespace 被拒绝时不会把空列表冒充完整列表。更多说明见 [Kubernetes](kubernetes.md)。

### 项目

本地终端旁的右侧栏有「项目」和「命令片段」（同远程终端旁的，见上面）。「项目」像主机一样把本地终端保存下来，可以分组，比如建一个分组「shellrs」，在里面开一个终端跑 Claude Code、一个终端跑 `cargo run`。每个终端记着自己的 shell 最后在哪个文件夹，退出 ShellRS 时开着的，下次启动自动在原来的文件夹重新打开。

- **新建本地终端**：右侧栏标题「项目」右边、「…」左边的加号，或空白处的右键菜单，新建一个不在分组里的终端；分组行右边的加号，或右键分组选「新建本地终端」，新建在那个分组里。不用填任何东西，马上打开，名称自动编号（分组里叫 shellrs 1、shellrs 2…，不在分组里叫 终端 1、终端 2…），列表和标签上的名字跟着 shell 和程序设的标题走，比如运行 Claude Code 时是「✳ Claude Code」；关掉标签、退出 ShellRS 后仍显示最后的标题，再打开时也先显示它，直到 shell 或程序设了新的；从没设过标题时才是这个编号的名字。右键「重命名…」可以起一个好记的名字，起了就固定显示它，不再跟着标题变；名称留空则恢复跟着标题。分组里的新终端从同组最后一个终端所在的文件夹开始，其余的从主目录开始。
- **分组**：加号旁边的文件夹按钮、空列表里的「新建分组」或空白处的右键菜单，只填名称（如 work）；分组不能嵌套，也不能重名。右键分组可以重命名或删除，删除分组连同其中的终端，开着的一起关闭标签，要确认。
- **列表**：和主机列表一样，分组在前，不在分组里的终端排在所有分组后面。分组行只有名称；终端行两行字：上面是名称，下面是它最后所在的文件夹（主目录写成 `~`），鼠标停在上面显示完整路径。开着的终端图标是绿色的，关着的是灰色的。点一个开着的终端就切到它的标签；点关着的，就在它最后所在的文件夹重新打开（文件夹已经不在时从主目录开始）。点分组行折叠或展开，和主机列表一样，下次启动还是这样。
- **拖动排序**：和主机列表一样拖动。分组拖到另一个分组的上半或下半，排到它前面或后面；终端拖到另一个终端的上半或下半，排到它前面或后面（可以是别的分组里的终端），拖到分组上就放进那个分组的最后，拖到列表下面的空白处就移出分组、排到最后。
- **关闭和删除**：关掉标签（或右键终端选「关闭」）后终端还留在分组里，只是变灰，下次点它再打开。不要了就点鼠标停在终端上时右边出现的删除按钮，或右键「删除」：没开着的直接删除、不再确认；开着的先确认，删除时一起关闭它的标签，其中运行的程序也会结束。「重新启动」在终端最后所在的文件夹重来，shell 用当前的设置。
- **记住所在的文件夹**：在终端里 `cd` 到哪，ShellRS 就记下哪里（看的是 shell 自己的当前目录，不用改 shell 配置）。macOS 和 Linux 上都能记；Windows 读不到，那里的终端总是从主目录开始。终端里运行的程序（比如 Claude Code）不影响记下的文件夹。
- **下次启动时恢复**：「项目」里哪些终端开着、什么顺序、哪个在前，随开随关随时记下，所以正常退出、崩溃或升级重启后，下次启动都按原来的顺序在各自的文件夹重新打开，原来在前的仍在前，关着的仍然关着。只恢复「项目」里的终端，⌘T 开的本地终端不恢复；分屏布局和终端里正在运行的程序也不恢复，要自己重新启动。从堡垒机拉起 ShellRS 时照样恢复，外部连接的标签在最前。
- **保留终端内容**：「项目」里的终端关掉标签或退出 ShellRS 时，记下它最后 1000 行输出（带颜色）；下次打开这个终端时先把这些内容显示出来，下面一行灰字「以上是上次关闭时的内容」，然后才是新的提示符。比如退出前执行过 `ls`，下次打开还能看到那份文件列表。内容以明文存在数据目录的 `terminal-output/` 里，删除终端或分组时一起删除；在「设置 › 终端 › 本地终端」里关掉「保留终端内容」会删除全部，以后也不再保留。几点限制：关闭时终端里正开着 vim、htop 这类全屏程序的话，不保留（它的画面不是输出）；ShellRS 崩溃时来不及保存，上一次保存的内容还在；「重新启动」不显示旧内容。

## 文件传输

SSH 主机的终端连上后，标签栏右侧有「上传文件…」和「下载文件…」两个按钮，标签的右键菜单和终端的右键菜单里也有这两项。文件经这个终端自己的 SSH 连接传输：不再登录，不再询问密码或验证码，跳板和代理照样走。

传输不用 SFTP，也不用 `scp`：ShellRS 在连接上另开通道，用主机的 shell 执行 `cat`、`wc`、`mkdir`、`mv`、`find` 这几个命令来收发文件，所以服务器上没有 SFTP 子系统也能用。主机要有 POSIX `sh`（Linux、BSD、macOS 和 BusyBox 设备都有；Windows 主机不支持）。只允许一个通道的堡垒机上用不了，请改用终端里的 ZMODEM（`rz` / `sz`）。

- **上传**：点「上传文件…」，在系统的选择框里选文件（macOS 上也能选文件夹），然后填要放进的远程文件夹。终端的 shell 报告过当前目录时默认填它，否则留空，留空就是登录目录；`~` 开头表示登录目录。文件夹不存在时会新建，文件夹连同里面的内容一起上传，同名文件会被覆盖。每个文件先写到目标旁边的临时文件（`名称.shellrs-part`），收全后才改名替换，所以中途断开或取消不会留下半个文件，原来的文件保持原样。新文件保留本机的权限位。
- **下载**：点「下载文件…」，填远程路径（文件或文件夹），选保存到本机的哪个文件夹，默认是「下载」文件夹。文件夹连同里面的内容一起下载，同名文件会被覆盖；主机上的符号链接不会跟进去。
- **进度**：窗口底部的状态栏显示正在传的文件和百分比，同时有几个传输时写明还有几个；点旁边的 × 取消全部传输。传输结束、失败或取消时弹出通知，失败的通知里有原因。
- 传输和终端共用一条连接，传大文件时终端会变慢。终端断开，经它进行的传输也随之中断。
- 没有断点续传，没有文件列表，也不能在界面里改名、删除或编辑远程文件：这些在终端里用命令完成。

## 下载与更新

安装包在 [GitHub Releases](https://github.com/dream10201/shell-rs/releases)：

| 系统 | 首次安装 | 自动更新 |
|---|---|---|
| macOS（Apple Silicon 和 Intel 共用一个包） | DMG，把 ShellRS 拖进「应用程序」 | 支持 |
| Windows x64 | 安装程序，按当前用户安装到 `%LOCALAPPDATA%\Programs\ShellRS`，不需要管理员 | 支持 |
| Windows x64 便携版 | zip，解压到任意可写的文件夹即可运行，数据在旁边的 `data` 里（见下文「Windows 便携版」） | 支持 |
| Linux x64 | AppImage | 支持 |

ShellRS 启动 30 秒后检查一次有没有新版本，之后每 6 小时检查一次。有新版本就在后台下载并校验，完成后标题栏右上角出现绿色的更新按钮。点开后，「查看更新内容」打开 GitHub 上的更新日志，「重启并安装」换成新版本并重新打开。重启会断开已打开的连接、停止文件传输和端口转发，对话框里会写明具体有哪些。

「设置 › 关于」里的「应用更新」只有三行：

- **当前版本**：下面写着现在的状态（已是最新、正在下载、已下载等），右边是版本号和一个按钮：平时是「检查更新」，下载好之后变成「重启并安装…」。构建号和平台在版本号的悬停提示里。
- **更新渠道**：稳定版适合日常使用；Beta 可以提前收到测试版本，稳定版发布时也会收到。切换后马上按新渠道检查（关掉自动升级时等你手动检查）。
- **自动升级**：关掉之后只在手动检查时才联网，发现新版本时由你决定是否下载。

- **校验**：更新清单由 ShellRS 的发布密钥签名，安装包按清单里的大小和 SHA-256 核对，任何一步对不上都不会安装。macOS 上还会核对新版本的开发者签名。
- **隐私**：检查更新只发送 ShellRS 的版本号、操作系统和 CPU 架构，不发送任何能识别这台电脑或用户的信息。匿名使用统计见「隐私」一节。
- **不能自动更新的情况**：从 DMG 里直接运行、没有放进「应用程序」文件夹、对安装位置没有写权限、Linux 上不是用 AppImage 运行，Windows 上既不是用安装程序装的、也不是便携版，或者是自己编译的开发构建。这时「关于」页会说明原因，有新版本时给出「前往下载页」。
- **退回旧版本**：数据库在升级到新结构之前会备份成 `shellrs.db.v<旧版本>.bak`。旧版本打开新结构的数据库时会拒绝打开，以免把新版本保存的数据弄乱；需要退回时，把备份改名回 `shellrs.db`。

### Windows 便携版

便携版是一个 zip（`ShellRS-<版本>-windows-x86_64-portable.zip`），里面是 `shellrs.exe` 和一个空的 `data` 文件夹，解压后运行 `shellrs.exe` 即可，不用安装。`shellrs.exe` 旁边有 `data` 文件夹的就是便携版：主机、凭据、设置、`known_hosts`、粘贴和生成的私钥、窗口位置和更新的下载都在 `data` 里，不写 `%APPDATA%`。「关于」页版本号的悬停提示里写着「便携版」。

- 先解压再运行：在 zip 里直接打开 `shellrs.exe` 时旁边没有 `data`，会当成普通的一份，数据写进 `%APPDATA%\shellrs`。
- 放在自己能写入的文件夹里，比如 `D:\Tools\ShellRS` 或 U 盘；不要放进 `Program Files`，也不要放进 OneDrive 这类会同步的文件夹。文件夹不能写入时不能自动更新，「前往下载页」给的是便携版的 zip。
- 不要改 `shellrs.exe` 的名字（更新换的是这个名字的文件），也不要删掉 `data`（没有它就不再是便携版）。在安装版的目录里建 `data` 不会让它变成便携版（卸载会删掉整个安装目录）。
- 自动更新和安装版一样在后台下载、校验；「重启并安装」或退出时换掉 `shellrs.exe`，`data` 不动。换下来的旧文件改名成 `.shellrs.exe.old-…` 这样的隐藏名字，新版本启动后删掉。
- 同一个便携版文件夹同一时间只给一个 Windows 账户用。它和安装版可以同时运行，各用各的数据，任务栏上也是两个按钮。
- **从安装版搬过来**：退出两边的 ShellRS，把 `%APPDATA%\shellrs` 里的文件拷进便携版的 `data`。粘贴和生成的私钥自动改指向 `data\keys` 里的那份；在同一台电脑上，保存的密码照样能用。
- **留在这台电脑上的**：
  - 密码和私钥口令照旧存进 Windows 凭据管理器，不随文件夹走：换一台电脑要重新输入；在别人的电脑上保存过的密码会留在那台电脑上，不想留就把密码留空（每次连接时询问）。它和安装版共用一份：在一边删掉主机或凭据、改了地址或用户名，可能清掉另一边还在用的密码，那边下次连接时会再问一次。
  - 第一次发系统通知时，Windows 在注册表里记下的通知身份（`HKCU\Software\Classes\AppUserModelId\com.shellrs.ShellRS.Portable`）。

## 隐私

ShellRS 不发送主机、凭据、会话内容、命令、文件名或路径，也不发送任何能识别这台电脑或用户的标识。ShellRS 自己联网的只有这两件事（连接主机本身除外）：

- **检查更新**：只发送 ShellRS 的版本号、操作系统和 CPU 架构，见「下载与更新」。
- **匿名使用统计**：发给 [Aptabase](https://aptabase.com)，用来了解安装量、每天有多少台设备在用、各版本的分布，以及哪些功能用得多。「设置 › 关于 › 隐私」里的「发送匿名使用统计」默认打开；关掉后不再发送，本机攒下的计数也一并清除。

开启「同步」后，ShellRS 把加密后的数据写进你选的文件夹（由网盘自己的程序上传），或直接上传到你填的 WebDAV 服务器或 S3 存储桶；ShellRS 不连接自己的同步服务器。文件整个加密，连设备名称（电脑名）、系统和 ShellRS 版本也在密文里，见「同步」。

每个统计事件都带 ShellRS 的版本号、操作系统的名称和版本（如 macOS 15.1、Windows 10.0.22631、Ubuntu 24.04）。事件只有四种：

| 事件 | 什么时候发 |
|---|---|
| `app_installed` | 第一次启动时发一次。数据目录里记着已经报过，换一个数据目录或删掉它会再报 |
| `app_started` | 每次启动 |
| `app_active` | 当天（UTC）第一次把窗口切到前台时；启动当天不再重复。macOS 上关了窗口、留在后台不算 |
| `usage` | 各功能的使用次数：从第一次使用算起满 4 小时，在下一次启动、切到前台或使用时汇总成一条 |

前三种附带这些设置和数量，取值都是固定的几种：CPU 架构、安装方式（安装程序、便携版、macOS 应用包、AppImage 或其他）、应用外观、界面语言、浅色和深色主题（内置主题的名字）、界面是否跟随主题、关键字高亮和自动升级是否打开、更新渠道、是否改过快捷键，以及保存的主机、凭据、端口转发、命令片段各有多少（只报档位：0、1-5、6-20、21-100、100+）。

`usage` 只有次数，没有内容，计的是：SSH 终端连上（另按跳板、代理、凭据、无密码、临时连接、外部连接分别计数）、本地终端、串口终端连上、Telnet 终端连上、端口转发开启（本地、远程、动态）、上传和下载文件、终端里的 ZMODEM 上传和下载、打开右侧栏的十一个工具、在「项目」里新建本地终端、命令片段和历史命令送进终端、终端查找、通知（程序、响铃、关键字），打开和关闭关键字高亮，以及从 `~/.ssh/config`、`~/.ssh/known_hosts` 导入主机（按次数，不计台数）。

- 计数先存在数据目录的 `analytics.json` 里，退出不会丢，之后再补发。离线或在内网里不影响使用：发不出去时等 1 分钟，之后每次加倍、最长 6 小时再试，而且只在使用 ShellRS 时顺带重试，空闲时不发任何请求。
- Aptabase 按请求的 IP 地址推断国家和地区，但不保存 IP。它区分设备用的是 IP 和 User-Agent 加上每天更换的随机盐算出的散列，所以看不到同一台设备跨天的行为。
- 自己编译的开发构建不发送统计。
